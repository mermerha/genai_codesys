# 大作业要求与验收清单

最后核对：2026-11-03  
依据：`genai/Final project_CHINESE.pdf`（2026-11-02 版本）与 `genai/大报告测试用例模板与示例.docx`。

## 目标

实现面向 CODESYS 的 ST 代码自动生成系统，基于现有大模型设计轻量级 Agent harness，并与现成 Agent 在 PLC 编程任务数据集上比较代码生成、编译、测试和资源消耗表现。

## 基础任务

### 数据集与规约

- [ ] 完成老师提供的 20 道公共题。
- [ ] 构建不少于 10 道自建题。
- [ ] 每道自建题记录来源类型。
- [ ] 网上题记录原始链接和改编内容。
- [ ] 合成题记录合成过程、人工改动和审核过程。
- [ ] 说明自建题的 PLC 场景合理性。
- [ ] 说明题库在任务类型、难度或其他维度上的多样性。
- [ ] 每道公共题和自建题都有 LTL 形式化规约。
- [ ] 规约覆盖主要功能、安全、状态变化、优先级和必要边界。

### 测试

- [ ] 每道公共题和自建题都有测试用例。
- [ ] 每个用例包含名称、所属题目、初始状态、输入与步骤、预期输出和覆盖内容。
- [ ] 正式测试后记录实际输出、通过/不通过和失败差异。
- [ ] 测试覆盖主要功能、正常流程和边界条件，不能只有少量正常用例。
- [ ] 同一道题在不同框架和模型下使用相同测试及判断标准。
- [ ] 汇总整体任务通过率和测试用例通过率。

手动测试允许；自动测试属于加分项，但若实现必须实际用于实验并保留证据。

### Agent 与模型

- [ ] 自研一个 PLC 代码生成 Agent harness。
- [ ] 自研 harness 至少支持 ST 代码生成和 CODESYS 编译。
- [ ] 明确任务组织、上下文管理、工具调用、编译修复和终止条件。
- [ ] 选择一个现成 Agent 框架作为基线。
- [ ] 选择不少于两个基座模型。
- [ ] 保存模型名称、版本/标识、参数、接入方式和资源限制。

### 四种实验设置

- [ ] 现成 Agent + 模型 A。
- [ ] 现成 Agent + 模型 B。
- [ ] 自研 harness + 模型 A。
- [ ] 自研 harness + 模型 B。
- [ ] 每种设置覆盖全部公共题和自建题。
- [ ] 实验条件公平、可复现并有原始证据。

最低按 30 道题计算，共至少 120 次任务运行；修复轮次和重跑不计入这 120 次最低任务覆盖数。

### 指标

- [ ] 首次编译通过率。
- [ ] 修复若干次后的累计编译通过率。
- [ ] 测试用例通过率。
- [ ] 整体任务通过率和单题通过情况。
- [ ] 修复次数、耗时和资源消耗等辅助指标。
- [ ] 如做形式化验证，记录通过、违反或超时及验证超时设置。

### 报告与提交

- [ ] 实验环境：软件/工具版本、模型配置、接入方式、资源限制。
- [ ] 数据集与 Spec：来源、生成/改编流程、逐题 LTL 规约。
- [ ] 自研框架设计：架构图或执行流程图、主要模块、关键策略和依据。
- [ ] 实验结果与分析：四种条件汇总、公平性、证据、成功与失败案例。
- [ ] 源码。
- [ ] 必要说明与运行文档。
- [ ] 原始实验记录和可追溯汇总结果。

## 进阶加分项

- [ ] 更真实、多样、合理的数据集。
- [ ] 更高的生成质量、稳定性、成本和时间效率。
- [ ] 自动测试。
- [ ] PLCVerif 等形式化验证。
- [ ] CODESYS 之外的 TIA Portal 等平台接入。

进阶项只有在基础闭环完成并稳定后再实施。

## 老师特别强调

- 自研框架不要求一定优于现成框架。
- 评分更看重实验公平、结果可信、分析有证据、框架逻辑清晰。
- 编译通过不等于功能正确，测试结果必须单独记录。
