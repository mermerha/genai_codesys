## D009：由 CPython 直接调用 CODESYS

- 日期：2026-11-05
- 状态：已确定
- 决定：项目迁移到纯英文根路径后，由 `src/plc_agent/codesys_runner.py` 直接启动 CODESYS 和 `codesys/scripts/compile_project.py`；不再使用 PowerShell 启动脚本或脚本暂存目录。
- 原因：减少一层平台脚本和路径转义，保持 harness 的主控制流都在 Python 内。
- 证据：正确 ST 返回 0 错误，错误 ST 返回结构化错误号、对象、位置和文本；两次均由 Python 集成测试直接执行。

## D010：功能块候选必须进入主程序引用链

- 日期：2026-11-05
- 状态：已确定
- 决定：编译 `FUNCTION_BLOCK` 候选时，harness 在临时工程的 `PLC_PRG` 中自动创建实例并调用该功能块。
- 原因：实际验证发现，只有创建但未被引用的功能块即使包含未定义标识符，应用构建仍可能显示 0 错误；这种结果不能代表候选代码真正通过编译。
- 证据：未引用时包含 `MissingSignal` 的候选被报告为成功；加入 `PLC_PRG` 引用后，CODESYS 对 `MotorControl` 返回错误号 32 和 46，并准确给出对象和位置。

## D011：模型 B 候选改为 qwen3.8-flash

- 日期：2026-11-09
- 状态：已确定
- 决定：按用户选择，将模型 B 由 `qwen3.5-flash` 改为 DMXAPI 模型 ID `qwen3.8-flash`，并固定使用 `reasoning_effort=none`。
- 原因：该模型默认高强度推理导致 `public_09` 在 300 秒内无输出；`low` 虽使 `public_09` 首次编译通过，但 `public_19` 仍在 300 秒超时。关闭思考后，三道不同难度预验证题均在 300 秒内完成：`public_03` 和 `public_19` 首次编译通过，`public_09` 经一次 JSON 解析修复后编译通过。
- 限制：这里只冻结模型身份和推理档位，不代表生成代码已通过功能测试。人工快速复核发现 `public_19` 候选在手动模式下可能同时输出相反方向命令，因此该次编译成功不能计为任务功能通过。
- 公平性：正式实验中，自研 harness 和现成 Agent 使用该模型时必须保持相同的 `reasoning_effort=none`；其他参数仍需在正式实验冻结前确定。
